# ImgRelay 需求文档

- 文档版本：0.1
- 日期：2026-10-10
- 产品形态：Skill + CLI
- 状态：需求草案，可作为实现与验收依据
- 项目名称：ImgRelay
- GitHub 仓库规划：`bingwu-devkit/imgrelay`
- CLI 命令：`imgrelay`
- Skill 名称：`imgrelay`

ImgRelay 是面向第三方中转站生图模型的通用调用工具。名称中的 Img 表示图片，Relay 表示中转，体现通过统一入口调用不同供应商的生图服务。

## 1. 背景与目标

用户希望在 Codex 中快速调用第三方中转站提供的生图模型。当前每次调用都可能需要重新阅读平台文档、确定地址与模型、组织请求、处理图片响应，重复工作较多。

工具将稳定的接口调用封装在 CLI 中，通过用户级配置保存中转站信息，并提供 Skill 指导 Codex 使用 CLI。接入过的供应商无需每次重新阅读官网文档；提示词、主题和用途由当前请求决定。

目标用户是使用 Codex 的个人开发者，同时支持用户直接在终端操作 CLI。

### 1.1 产品目标

- 用户配置一次地址、密钥和默认模型，即可在不同项目中复用。
- Codex 能根据自然语言需求调用 CLI，完成生图、保存图片和展示结果。
- 同样采用 OpenAI Images 协议的中转站共用调用逻辑。
- 模型列表查询、参数能力配置和实际生成结果分别记录，避免把“模型可见”当作“全部能力已验证”。
- 配置、日志及生成记录不暴露密钥。

### 1.2 已确认的原则

- 采用 Skill + CLI；CLI 承担配置管理和实际 API 调用。
- Skill 是通用生图调用入口，不绑定特定设计 Skill、风格、主题或配色。
- 默认支持第三方 OpenAI Images 兼容接口，并允许配置多家供应商。
- 配置供应商无需修改代码；非标准接口通过后续适配器扩展。
- 第一版不建设网页工作台或 MCP 服务。

## 2. 首版范围

| 优先级 | 能力 | 范围 |
| --- | --- | --- |
| P0 | 供应商管理 | 添加、查看、修改、删除，设置默认供应商和模型 |
| P0 | 密钥管理 | 隐藏输入、从文件导入、环境变量引用、更新与移除 |
| P0 | 模型发现 | 查询 `/models`，缓存结果，允许手动填写模型 ID |
| P0 | 配置检查 | 检查配置、鉴权和模型列表，不自动发起付费生成 |
| P0 | 文生图 | 提示词、模型、尺寸、数量、质量及图片格式 |
| P0 | 结果保存 | 处理 Base64 或图片 URL，保存原图和生成记录 |
| P0 | Codex Skill | 选择配置、准备提示词、调用 CLI、展示图片 |
| P0 | 机器输出 | 稳定的 JSON 结果、错误分类和退出码 |
| P1 | 图片编辑 | OpenAI Images Edits，多图输入与模型能力约束 |
| P1 | 扩展协议 | Responses、自定义异步任务等适配器 |
| P1 | 使用便利性 | 配置导入导出、历史检索、系统凭据存储集成 |

首版不提供模型服务、中转代理、平台密钥分组管理、计费平台或自动提示词优化。配置检查不承诺推断出供应商支持的全部参数。

## 3. 职责划分

| 组件 | 职责 |
| --- | --- |
| Skill | 理解需求、准备提示词、确定显式参数、调用 CLI、呈现结果 |
| CLI | 管理供应商与密钥、校验输入、执行请求、保存文件、输出状态 |
| 用户级配置 | 保存地址、默认模型、默认供应商和参数覆盖，不包含密钥明文 |
| 凭据存储 | 保存密钥或其外部引用，供 CLI 读取 |
| 协议适配器 | 构造请求、处理协议特有行为、解析响应 |
| 模型能力配置 | 记录已知模型限制及供应商差异，供 CLI 判断参数是否适用 |

配置默认放在当前用户目录，跨项目复用；生成结果默认放在当前工作目录下的 `output/imagegen/`。Skill 中不保存某家供应商的密钥。

## 4. 用户流程

### 4.1 首次配置

1. 用户安装 CLI 和 Skill。
2. 通过 CLI 交互式配置供应商名称、API 地址、密钥来源和默认模型。
3. CLI 检查配置，并在接口可用时查询模型列表。
4. 用户选择默认模型和默认供应商。
5. 保存配置。此流程不自动生成图片。

### 4.2 在 Codex 中生成图片

1. 用户提出生图需求，可以指定供应商、模型、尺寸和保存位置。
2. Codex 加载 Skill，读取 CLI 返回的非敏感配置摘要。
3. 使用用户指定值；未指定时读取对应默认值。
4. 准备提示词并调用生成命令。
5. CLI 等待结果、保存原图及记录，返回文件路径和实际尺寸。
6. Codex 展示图片，说明使用的供应商、请求模型和保存位置。

常见请求示例：

- “生成一张赛博朋克城市，横版，保存到当前项目。”
- “用 Cubence 生成一张猫。”
- “使用供应商 demo，模型选择 xxx，生成两张图片。”

### 4.3 新增其他中转站

- 同协议供应商：新增名称、地址、密钥和模型配置即可复用已有适配器。
- 同协议但有差异：通过端点、参数默认值和能力覆盖处理已支持的差异。
- 非标准协议：说明需要新增适配器；首次接入再阅读对应文档，不猜测请求格式。

## 5. 供应商与凭据配置

### 5.1 供应商字段

| 字段 | 必需性 | 含义 |
| --- | --- | --- |
| 名称 | 必需 | 用户指定的唯一标识，例如 `cubence` |
| 协议 | 必需 | 首版默认 `openai-images` |
| Base URL | 必需 | API 基础地址，推荐明确包含 `/v1` |
| 凭据引用 | 必需 | 本机密钥存储、环境变量或外部文件的引用 |
| 默认模型 | 生成前必需 | 可以从列表选择，也可以手动输入 |
| 默认生成参数 | 可选 | 尺寸、数量、质量和输出格式 |
| 端点覆盖 | 可选 | 标准路径以外的生成或模型列表路径 |
| 能力覆盖 | 可选 | 某个供应商下特定模型的参数限制 |
| 超时 | 可选 | 生成请求等待时间，可由命令覆盖 |

地址拼接必须避免重复 `/v1`、遗漏路径或重复斜杠。配置检查应展示最终请求地址，供用户核对。

### 5.2 Cubence 初始配置参考

| 配置项 | 值 |
| --- | --- |
| 名称 | `cubence` |
| 协议 | `openai-images` |
| Base URL | `https://api-lb.cubence.ai/v1` |
| 默认模型 | `gpt-image-2.5-flare` |
| 默认尺寸 | `auto` |
| 默认数量 | 1 |
| 默认质量 | `high`，已在本次调用中验证 |
| 默认输出格式 | `png`，已在本次调用中验证 |

该配置是已验证的供应商预设示例，不限制其他供应商使用自己的模型和默认参数。

### 5.3 密钥管理要求

- 支持隐藏输入；支持从用户指定文件导入密钥，或引用环境变量。
- 文件导入默认将密钥保存到用户级凭据存储，不要求长期依赖项目中的临时 `key` 文件。
- 首版可使用仅当前用户可访问的独立凭据文件；实现时应设置并验证对应平台的访问权限。
- 明确区分“导入密钥”和“引用外部文件”；引用模式下文件移动或丢失应给出可操作错误。
- 不要求密钥必须以 `sk-` 开头，不将某家供应商的命名规则应用到其他供应商。
- 查看、列表、JSON 输出、错误信息和生成记录均不输出密钥明文。
- 不通过命令行明文参数传入 Key；Codex 应传凭据引用或密钥文件路径。
- 删除供应商时，移除仅属于它的已存凭据；共享环境变量或外部文件不随之删除。
- 修改地址或凭据后，使对应模型缓存失效，避免复用其他地址或密钥的查询结果。

## 6. 模型发现与能力判断

### 6.1 查询模型列表

- 标准实现向供应商的 `GET /models` 发送 Bearer 鉴权请求。
- 解析 `data[].id`，保留供应商返回的原始模型 ID，不重命名或补全。
- 展示所有可见模型；有可靠类型信息时按类型分类，没有时仅提供生图候选筛选。
- `gpt-image-` 等名称匹配属于候选判断，不作为模型是否支持生图的唯一依据。
- 支持显式刷新；缓存应包含供应商配置版本和查询时间。
- 接口不存在、列表不完整或无法查询时，仍允许手动配置模型，展示“未通过列表验证”。
- 不因为模型未出现在列表中就一律禁止生成；以明确的 API 错误和调用结果进一步判断。

### 6.2 能力配置

模型列表一般不能完整描述尺寸、质量、数量、格式或编辑能力。CLI 需维护已知模型的能力，并允许供应商按模型覆盖。

- 生成参数优先级：本次命令指定值 → 供应商默认值 → 工具默认值。
- 参数校验依据：供应商能力覆盖 → 已知模型能力 → 未知能力时交由上游验证。
- 覆盖配置不能因为用户传了参数而被跳过；已知不支持的参数应说明原因。
- 未知模型不被限制在硬编码的模型名称枚举中，也不强制要求 `gpt-image-` 前缀。
- 只发送本次需要的参数，不把全部可选参数无条件附加到请求中。
- GPT Image 标准配置不默认发送 `response_format`；该参数在官方 GPT Image 接口中不受支持。
- 能力来源标记为官方文档、供应商覆盖或调用验证，区分未知能力和已确认支持。
- 首版不自动探测每一种参数；探测生成能力会产生付费请求，应由用户显式触发。

## 7. 生图与响应处理

### 7.1 生成请求

- 使用标准 `POST /images/generations`，JSON 请求体和 Bearer 鉴权。
- 必须具备模型与非空提示词。
- 提示词支持直接输入、从 UTF-8 文件读取，以及标准输入。
- 支持模型、尺寸、数量、质量、输出格式和输出目录设置。
- 提示词内容原样交给 CLI，不由 CLI 自动添加风格、品牌、用途或负面约束。
- 首版使用非流式生成；合理提示请求可能需要等待，并支持超时配置。
- 数量超过已知模型限制时应说明限制，不擅自拆成多次付费生成。

### 7.2 图片响应

- 优先解析 `data[].b64_json`，解码并保存图片。
- 兼容 `data[].url`，下载图片并保存；不把供应商 API Key 转发给其他下载域名。
- 同一条结果同时包含 Base64 和 URL 时，优先保存 Base64，避免重复下载。
- 返回多张图片时保存全部结果，记录请求数量与实际返回数量。
- 记录图片的实际格式、尺寸和字节大小，不仅依赖请求中的格式与尺寸。
- 保留原始输出，不为匹配请求尺寸而自动缩放、裁剪或修图。
- 响应中没有有效图片、解码失败或下载失败，应归类并保留已有成功文件。
- 若图片生成成功但保存失败，不重新发起生成请求；输出已知任务结果与保存失败原因。

### 7.3 输出文件与记录

- 默认在 `output/imagegen/` 保存；用户可明确指定其他目录或文件名。
- 默认采用唯一名称，不覆盖已有图片；显式覆盖需由命令参数表达。
- 多图输出具有可追溯的序号和统一的生成记录。
- 生成记录包含供应商、请求模型、时间、提示词或提示词文件、请求参数、实际尺寸、文件路径和状态。
- 上游有返回模型标识时单独记录；没有时仅记录请求模型，不声称已确认底层模型身份。
- 用量仅在上游实际返回时记录；首版不把官方价格当作第三方账单。
- 不保存请求鉴权头、密钥明文或含访问凭据的原始下载链接。
- 部分结果保存成功时返回部分成功状态，并列出已保存文件和失败项。

## 8. CLI 命令设计草案

以下是 ImgRelay 的 CLI 命令约定，尚未实现。

| 命令 | 用途 |
| --- | --- |
| `imgrelay provider add cubence` | 交互式添加供应商与凭据来源 |
| `imgrelay provider list` | 展示供应商摘要及默认项 |
| `imgrelay provider show cubence` | 查看脱敏配置 |
| `imgrelay provider edit cubence` | 修改地址、模型、密钥和参数 |
| `imgrelay provider use cubence` | 设置默认供应商 |
| `imgrelay provider remove cubence` | 移除供应商及其独占凭据 |
| `imgrelay models --provider cubence` | 查询或查看缓存的模型列表 |
| `imgrelay models --provider cubence --refresh` | 显式刷新模型列表 |
| `imgrelay doctor --provider cubence` | 检查配置和只读接口 |
| `imgrelay generate --prompt-file prompt.txt` | 使用默认供应商和模型生成 |
| `imgrelay generate --provider cubence --model xxx --prompt-file prompt.txt` | 本次覆盖供应商与模型 |

公共选项应包括 JSON 输出；生成命令应支持尺寸、数量、质量、图片格式、输出目录和超时。非交互环境缺少必需信息时直接返回结构化错误，不进入等待输入状态。

### 8.1 机器输出约定

- `--json` 下标准输出只包含一个最终 JSON 对象，进度和诊断信息写入标准错误。
- 结果包含状态、供应商、请求模型、图片路径、实际尺寸、记录路径和可选用量。
- 错误包含稳定的错误类别、可操作说明和适用时的上游 HTTP 状态码。
- JSON 不包含原始 Base64 图片数据或密钥；由 Codex 根据返回路径展示图片。
- 退出码区分成功、输入或配置错误、上游调用失败、文件保存失败、部分成功和用户中断。
- 调用者依据错误类别判断下一步，不解析易变的自然语言错误文字。

## 9. 错误与恢复规则

| 场景 | 处理方式 |
| --- | --- |
| 未配置供应商或默认模型 | 返回配置错误并提示对应配置命令 |
| 密钥不存在或环境变量未设置 | 提示凭据来源，不打印密钥内容 |
| 鉴权失败 | 提示检查密钥、权限或平台分组 |
| 模型不可用 | 提示刷新模型列表或手动调整，不自动换模型 |
| 参数不支持 | 指明相关参数并保留请求记录，不自动降低质量或更改尺寸 |
| 限流或余额不足 | 展示上游原因，不擅自切换供应商 |
| 模型列表接口不可用 | 允许手动配置，标记查询状态 |
| 生成请求超时或网络断开 | 标记结果未知；上游可能仍在生成，不默认重提请求 |
| 有图但本地保存失败 | 保留已有文件，说明失败原因，不重新生图 |
| 用户中断 | 结束本地等待，说明无法保证取消已提交的上游请求 |

默认不对生成 POST 请求进行自动重试；若使用 SDK，应检查并调整其隐式重试行为。配置检查或模型列表等只读请求可采用有限重试。

## 10. Skill 行为要求

- 描述和触发条件聚焦于通过已配置的第三方中转站生成或编辑图片。
- 优先读取本机 CLI 配置，无须重新阅读已经接入供应商的官网文档。
- 只读取脱敏摘要；密钥读取和 HTTP 鉴权由 CLI 完成。
- 用户未指定时使用默认供应商和模型，不反复询问相同配置。
- 没有默认配置时提示配置入口，不猜测地址或替用户选其他付费平台。
- 用户明确要求生成时调用生成命令；仅询问配置或能力时不付费生图。
- 长提示词优先使用提示词文件，避免 shell 引号、换行和特殊字符损坏内容。
- 从 CLI 的 JSON 输出读取图片位置，展示图片与关键元数据。
- 尊重调用结果，不自动筛选、修图、追加生成或切换模型。
- 不修改当前项目代码或替换已发布头像，除非用户另有明确要求。

## 11. 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 首次配置 Cubence | 保存地址、凭据和默认模型，跨项目可读取，未产生生成请求 |
| AC-02 | 配置第二家同协议供应商 | 不修改代码即可新增、切换默认供应商 |
| AC-03 | 查看配置与错误输出 | 人类输出、JSON、日志和生成记录均无密钥明文 |
| AC-04 | 查询模型列表 | 展示接口原始模型 ID，记录时间，刷新后更新缓存 |
| AC-05 | 不支持 `/models` 的平台 | 可手动配置模型；查询失败不阻断明确的生成调用 |
| AC-06 | 未知模型 ID | 不因本机枚举或名称前缀拒绝，按已知覆盖或上游响应处理 |
| AC-07 | 默认配置生图 | 用户只提供提示词即可使用默认供应商和模型 |
| AC-08 | 单次参数覆盖 | 命令指定的供应商、模型或参数仅影响本次调用 |
| AC-09 | Base64 与 URL 响应 | 两种响应均能保存正确图片并输出路径 |
| AC-10 | 请求与实际尺寸不同 | 原图保持不变，记录实际尺寸 |
| AC-11 | 多图与部分失败 | 保存全部成功结果；部分失败可通过状态和退出码识别 |
| AC-12 | 模型或参数错误 | 给出明确类别，不自动换模型、改参数或追加付费调用 |
| AC-13 | 超时 | 不自动重发生成 POST，说明结果未知 |
| AC-14 | JSON 模式 | 标准输出可整体解析，无进度文本、密钥或 Base64 数据混入 |
| AC-15 | Codex 调用 | Skill 可根据自然语言需求调用 CLI 并展示本地图片，无须重读已接入平台文档 |
| AC-16 | 文件重名 | 默认不覆盖已有图片，生成记录能够定位本次结果 |
| AC-17 | 模型缓存隔离 | 更新地址或凭据后，不复用旧查询结果 |

供应商兼容性可通过本地模拟响应验证；上线前至少完成一次用户授权的 Cubence 实际生成验证。不为了测试遍历全部模型或参数组合。
